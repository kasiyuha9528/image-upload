# 要件定義書 — 画像アップロード機能（案件No.05）

## 1. 目的
ドラッグ & ドロップで画像をアップロードし、Supabase Storage に保存して公開 URL を返す。
アップロード済みの画像はサムネイル一覧で確認できる。

## 2. 機能要件
| No | 要件 | 内容 |
|---|---|---|
| F1 | アップロード UI | ドラッグ & ドロップ（クリックでのファイル選択も可） |
| F2 | 複数ファイル | 一度に複数枚ドロップできる。1枚ずつ判定し、OK のものだけアップロード |
| F3 | 保存 | Supabase Storage の公開バケットへ、ブラウザから直接アップロード |
| F4 | 公開 URL | アップロード後に公開 URL を表示（コピー可） |
| F5 | 一覧表示 | アップロード済み画像をサムネイルで表示（新しい順） |
| F6 | 即時反映 | 成功した画像は再読み込みなしで一覧に追加される |

## 3. 入力チェック（達成基準）
| No | 基準 | 判定方法 |
|---|---|---|
| C1 | 5MB 以上を弾く | 5MB = 5,242,880 バイト。**ちょうど 5MB も NG**（5,242,879 バイトまで OK） |
| C2 | jpg / png / webp 以外を弾く | 拡張子 `.jpg` `.jpeg` `.png` `.webp`（大文字小文字を区別しない）かつ MIME タイプが `image/jpeg` `image/png` `image/webp` |
| C3 | プレビュー即時更新 | F6 と同じ |

チェックは 2 段構え：
1. 画面側（すぐにエラー表示）
2. Supabase バケット設定（容量上限・許可 MIME タイプ）で、画面をすり抜けたものも拒否

## 4. 決定事項
| 項目 | 決定内容 |
|---|---|
| ログイン | なし（誰でもアップロード可） |
| 削除機能 | アプリには付けない。削除は Supabase の管理画面から手動で行う |
| 保存ファイル名 | ランダム ID ＋ 拡張子（日本語名や同名ファイルの上書きを防ぐ） |
| アップロード方式 | ブラウザ → Supabase Storage へ直接（Vercel の 4.5MB 制限を回避） |

## 5. 技術スタック
- Next.js（App Router）＋ TypeScript ＋ Tailwind CSS
- Supabase Storage（@supabase/supabase-js）
- npm、GitHub（公開リポジトリ）、Vercel（GitHub 連携でデプロイ）

## 6. 全体のフロー
```
[ブラウザ]
 画像をドロップ（複数可）
   ↓
 1枚ずつ画面側チェック（サイズ・拡張子・MIME）── NG → その画像だけエラー表示
   ↓ OK
 Supabase Storage に直接アップロード（ファイル名はランダム ID）
   ↓
 Supabase 側でも再チェック（バケットの容量・形式制限）
   ↓ 成功
 公開 URL を取得 → 一覧の先頭に追加して即表示

[ページを開いたとき]
 Storage のファイル一覧を取得 → サムネイル表示（新しい順）
```

## 7. 対象外
- ログイン / ユーザーごとの画像管理
- アプリ上での削除・編集
- 画像の圧縮・リサイズ
